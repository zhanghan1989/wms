# 产品主表整理说明

日期：2026-04-05

## 目标

本轮整理的主线，是把系统从以 `SKU` 为库存和检索核心，逐步切换为以 `产品ID` / `master_products` 为核心，并把产品主表管理页面从“叠加覆盖修补”收回到稳定的基础实现。

## 已完成的整理

### 1. 数据模型与库存口径

- 新增了 `master_products` 主表，并将产品属性逐步收敛到主表。
- `SKU` 与主表通过 `productId` 关联，不再承担产品总库存口径。
- 新增了主表箱内库存表 `master_product_box_inventory`，箱号与主表产品关联，不再以 `SKU` 作为箱内库存主键。
- 主表总库存 `master_products.stock_qty` 改为按主表产品维度汇总。

## 当前仍需继续整理的点

### 1. `app.js` 全局仍有历史乱码

虽然产品主表管理自己的覆盖层已经收口，但 [app.js](C:/zhanghan/01-IT/03-soft/002-WMS/apps/api/public/app.js) 文件头和多个公共函数区域仍残留大量历史损坏文本。  
这部分不是产品主表管理单独的问题，而是整个前端总控文件的历史污染。

直接影响：

- `node --check apps/api/public/app.js` 目前仍不能稳定通过
- 后续继续删冗余时，容易再次把已修好的页面带坏

### 2. 前端总控文件仍有多层历史 override / legacy 结构

这轮只收口了“产品主表管理”本身；`SKU 管理`、`编辑弹框`、`错误弹框`、库存页等区域，仍可能存在：

- 原函数
- 中段 clean override
- 文件尾部 final override

这些仍需继续分块清理。

### 3. 建议的后续顺序

建议继续按以下顺序推进：

1. 先恢复 [app.js](C:/zhanghan/01-IT/03-soft/002-WMS/apps/api/public/app.js) 全局可稳定通过 `node --check`
2. 再单独清 `SKU 管理`
3. 再清 `新增SKU / 编辑SKU` 弹框相关重复实现
4. 最后再处理库存页和其他 legacy 区域

## 本轮原则

- 不再新增新的 override 层
- 一次只收一个功能块
- 每一块都先确保：
  - 语法可检查
  - 页面路径单一
  - 文案无乱码
