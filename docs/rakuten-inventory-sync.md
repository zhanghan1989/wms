# 乐天库存自动同步

入口：乐天自动处理中心 → 库存自动同步 → 映射、预览与记录。

## 启用前

1. 部署时执行新增的 Prisma migration `20261015040000_rakuten_inventory_sync`、`20261015050000_rakuten_inventory_catalog`、`20261015060000_rakuten_inventory_guards`、`20261015070000_rakuten_inventory_hourly`、`20261015080000_rakuten_inventory_operations`。开发过程不连接、迁移生产数据库。
2. 店铺需要 InventoryAPI 2.1 的 `inventories.bulk.get_2.1`、`inventories.bulk.upsert_2.1` 权限。
3. 还需要 ItemAPI 2.0 的 `items.search`、`items.get`、`items.bulk.get` 权限及相应商品API服务资格，用实际商品的 `variants` 校验管理番号。库存接口能接受不属于真实商品的孤立库存，因此不能单靠库存回读验证商品存在。
4. 点击“读取乐天在售SKU并自动匹配”。后台使用 `items.search` 的 `cursorMark=*` 开始、每页最多100件商品，不受 offset 10000 的限制；不设置在库大于0筛选，所以缺货SKU仍保留。
5. 系统只查询该店铺相关的 WMS SKU，优先用 `merchantDefinedSkuId` 精确匹配 SKU/rbSku/fbmSku；主编号没有匹配结果时才尝试精确的 `variantId`。不按商品名称匹配、不跨店铺匹配，也不直接把未关联的WMS产品ID当作乐天SKU。仅启用中、非肩带本体/配件的主产品能成为自动候选。
6. 唯一匹配自动创建映射，安全库存默认为0；全局和店铺库存开关仍需人工开启。未匹配、多产品对应或自动关系变化的SKU留在“仅需人工处理”列表，可预填乐天编号后填写产品ID修正。已有手动映射、安全库存和停用设置保留。商品管理番号转小写，SKU管理番号区分大小写；数据库索引使用二进制排序规则保留区别。
7. 开启店铺订单导入。先执行完整订单导入，再预览和手动同步一小组映射。验证成功后开启店铺库存开关及自动化中心的全局库存开关。

新部署的全局库存开关、各店铺库存开关均默认为关闭，不会自动向乐天写入。

## 店铺商品清单

手动读取立即返回持久化任务ID，页面每3秒读取进度，避免大店铺HTTP请求长时间阻塞。游标、分批数据和进度共同提交；完整遍历后才原子切换可见版本。读取中断或失败不会用半份清单替换原同步范围。进程中断后可在锁过期后再次点击读取，或由下一轮启用的库存任务恢复保存的游标；明确失败的任务重新完整读取。

启用的店铺在每天日本时间17:30的库存任务中，先完整刷新乐天在售清单并自动匹配，不再以是否超过24小时决定要不要刷新。读取失败时保留原清单供查看，停止该店铺本轮同步并记录失败原因，不使用旧清单继续上传；其他店铺继续独立处理。手动预览要求已有24小时内完整清单。系统只对该清单中已匹配、启用的数量管理在售SKU计算并上传库存；仓库/下架、非数量管理、销售时间外商品跳过。销售起止时间在每次同步时判断，未来销售商品到时间后可自动进入范围。自动映射也会再次核对当前WMS关联，发现变化则停止，要求刷新并处理冲突。

`items.search` 的新增/删除索引可能延迟最多24小时；仅返回manageNumber的删除记录会忽略。每次计划使用 `items.bulk.get` 分组50个商品核对真实商品/SKU及最新在售、隐藏和销售期状态，防止搜索索引延迟导致下架商品被上传；手动映射例外验证仍用 `items.get`。批量权限缺失直接停止并提示，不静默退回逐商品请求。人工停用SKU只停止后续更新，不清零乐天库存。

清单按50个SKU分页，支持只看未匹配/冲突；传统映射表最多展示前200条，任意清单页可进入人工修正，保留该映射的安全库存和开关。旧清单保留至少2天用于诊断，完成新版本后清理超期旧行，不删除映射或同步记录。

## 调度和数量

库存使用独立任务 `rakuten-inventory-sync`，按日本时间每天17:30启动（每天一次）。订单、物流、回传和邮件保留每20分钟原流程。原流程和“自动处理检查”按钮不再启动库存，手动库存操作使用库存页的预览、确认。店铺没有最近25分钟内完整导入订单、存在导入警告、停用或License过期时停止该店铺。每批写入前再次检查订单导入新鲜度，长任务过期也会停止。库存任务不改变其他定时开关。

普通产品只使用箱内可用库存，不加载BOM。肩带使用剩余成品＋剩余材料按BOM换算的可组装数。本体、配件不允许单独配置映射。

可用库存先通过现有库存计算扣除 FBA 和未出库拣货批次预占，再扣除尚未进入拣货批次的海外仓待发货订单；已在 created/picked/yamato_exported/completed 批次中的来源订单不再重复扣减。肩带订单先占成品，不足部分占用 BOM 材料。订单、批次、箱库存的本次数量计算使用同一个 RepeatableRead 数据库快照。

按当前业务规则，待发货订单取 WMS 已导入、未删除、未仓库出货的乐天订单，以及 WMS 的可履约亚马逊文件订单/手动订单；明确中国发货的订单排除。亚马逊 API 分析专用记录沿用现有业务边界，不重复参与仓库占用。

每个目标SKU独立使用全量剩余可用库存，共用材料和多店铺不分配库存（用户已选择此规则）。因此多个SKU的上架数量不能合计为可同时销售总量；每天更新仍有日内库存变化、新订单并发和超卖窗口。可为每条映射设置安全库存。

上传值为 `min(99999, max(0, 可用数量 - 映射安全库存))`。0库存也上传。无变化的SKU不写入。停用映射或店铺仅停止后续更新，不清空乐天现有库存。

## 更新保护和记录

- 预览保存服务端计划、用户、店铺和10分钟有效期；确认时重新计算，发生变化则拒绝旧预览。预览只能执行一次。
- 所有库存预览、配置和写入共用数据库租约锁，跨服务进程避免重复写入，外部调用前检查锁仍有效。
- 写入每批最多400条、每秒最多一次；库存批量读取及单商品/搜索读取每秒最多4次。批量商品校验每次50个商品、每秒最多一次。读取失败可以有限重试；写入失败或超时不自动重放。
- 写入前再次读取乐天库存，检查数量和配送设置与计划一致。按最新读取值保留 `operationLeadTime`、`shipFromIds`，使用 `ABSOLUTE` 模式提交。仅复制写入支持的字段，不传回 created/updated 或内部计划字段。
- 紧邻写入前再次计算本地库存和订单预占；变化时停止本轮。远端API没有在文档中提供乐天订单下单与绝对值写入之间的条件更新事务，因此这些检查不能完全消除并发销售窗口。
- `204` 后必须回读，核对数量和配送设置；不一致或写入结果未知时标记需检查，不继续盲目重试。前面已完成的批次保留实际结果，无跨店铺/跨批次原子回滚。
- 每店展示最近20次预览/同步记录；失败说明不保存凭证和任意远端响应正文。

## 每天17:30检查、差异更新与完整校验

每轮按最新在售清单和WMS关联确定范围，计算本地可售数，再用 `inventories.bulk.get` 每批最多1000个SKU比对乐天实际数量和配送设置。

- 当天已经完成完整核对的轮次只对数量有差异、或尚未确认当前目标数量的SKU查询真实商品详情。其余SKU跳过商品详情校验和写入。
- 首次运行，以及日本日期变化后首次成功执行的轮次，完整校验范围内全部商品。通常是每天17:30；若该轮关闭、失败或忙碌，则在下一次成功执行时补做，不额外启动另一套写入任务。
- 手动预览始终完整校验；仅预览不改变完整核对时间。手动确认同步成功可完成当天完整核对。
- 本地数量没变也必须读取乐天实际库存。例如同一小时内卖出5件、入库5件，WMS净库存不变，但乐天已扣单；只比较上次上传数会漏补，不使用缓存直接跳过库存读取。
- 映射保存最后确认数量和时间。只有写入并回读一致，或真实读取已与目标一致后，才更新确认值；写入失败不记成功。人工修正映射清除旧确认值，重新校验。
- 记录区分“变化检查”与“完整核对”，展示范围数、实际比对数、商品详情校验数、更新数和跳过数。完整核对日期和范围基准只在整轮成功后更新；已回读成功批次的数量确认可保留。
- 自动化中心库存下一次计划时间取独立任务的真实每日17:30计划时间；原每20分钟任务不重复执行库存。

## 大店铺性能与后台任务

每天的一轮内各店独立读取初始库存；写入前仍对本批产品重新读取一致性快照，不复用旧预占。待发货查询只选必要字段，按产品汇总；物理库存读取限制到目标成品、材料以及共用这些材料的待发货肩带，保留其他肩带对共享材料的真实占用。普通产品不加载BOM。

预览及手动执行均先持久化任务、再返回任务ID，页面每2.5秒查询进度，不让HTTP请求等待整店计算。关闭页面不会取消后台任务，重新打开时恢复当前用户最近的有效预览或活动任务。预览有效期从计算完成开始计10分钟。服务重启后，下次获得库存租约时将遗留的计算/复核/写入记录标为中断需检查；涉及写入中断的店铺同时关闭开关并保留提醒，不自动重放写入；锁有效期为10分钟。

## 异常暂停与恢复

以下情况关闭对应店铺库存自动同步开关，并持久化原因；自动化中心持续显示所有暂停店铺（最多50个）的提醒，店铺配置显示详细原因。不会发送邮件或外部消息。

- 本轮将至少10个原本有库存的SKU变为0，且达到原本有库存SKU的50%。少量正常缺货照常同步。
- 可同步SKU较最近一次成功同步减少超过50%，且原基准至少10个。清单/匹配异常不会静默缩小同步范围后继续上传。
- 定时同步连续失败3次，成功后计数清零。
- 有已尝试写入但未全部回读确认的SKU，立即暂停，避免下一轮自动覆盖未知结果。

暂停后不能直接重新开启开关。需检查原因、刷新清单（如涉及映射）、重新预览并手动确认同步成功，才清除异常和重设SKU基准；店铺开关仍保持关闭，之后由用户开启。手动预览会展示全量变更数及将归零数，允许人工确认真实的批量缺货或业务范围调整。

## 接口

### 连接检测、预览解释和异常SKU

“检测连接与权限”只调用读取接口，逐项显示 `items.search`、`items.get`、`items.bulk.get`、`inventories.bulk.get_2.1` 的结果。空店铺或无合适SKU样本时标记未验证。`inventories.bulk.upsert_2.1` 始终提示未验证，不通过试写库存来检测权限，也不将读取成功视为写入权限已开通。

预览支持全部、仅看变化、仅看将归零，先筛选再按50行分页；汇总与确认仍对应完整计划。成品和可组装数已扣除FBA及拣货占用；待发货预占影响表示扣减剩余成品和共享材料后，可售数量减少了多少，再扣安全库存并限制0至99999。普通产品不计算BOM，显示“—”。旧预览缺少解释字段时显示“—”，不猜测历史数量。

正常读取成功但个别SKU未返回库存，或真实商品中已不存在该SKU、下架、销售期无效时，持久化到异常SKU待处理列表，不上传、不自动清零；其余有效SKU继续。异常至少10个且达到范围50%时暂停整店。HTTP请求失败、权限异常、未知或重复返回记录、数据格式错误、订单不完整、写入前变化、未知写入结果等仍停止，不能误判成单个坏SKU。

隔离项保留映射启用设置，每轮重新检查；正常校验并确认数量成功后清除异常，手动修正并验证映射也可清除。存在隔离项的轮次标记部分完成、不推进每日完整核对日期、不清除整店异常暂停原因，逐批已完成记录保留。未启用、关系冲突等原有清单范围规则仍生效。

### 历史明细保留

每天日本时间03:10独立执行维护，库存开关关闭时也会清理。过期预览超过7天、成功计划超过30天、失败/部分完成/中断计划超过90天后清除完整计划明细；任务摘要、统计及失败原因继续保留。有效预览、规划、复核和写入中的任务不清理；使用库存租约避免与同步并发。每类最多10批、每批500条，积压时分天清理。维护不调用乐天接口。

前缀 `/rakuten-rms-api/connections/:connectionId/inventory`，沿用现有乐天管理端的登录认证：

- `GET /`：店铺开关、前200个映射、清单摘要、最近记录。
- `POST /catalog/refresh`：开始后台读取店铺商品清单并自动匹配，仅修改WMS映射，不写乐天库存。
- `GET /catalog?page=1&issuesOnly=true`：读取任务进度及分页清单。
- `PUT /enabled`：店铺自动同步开关。
- `PUT /mappings`：验证商品和库存后新增/更新映射。
- `POST /mappings/:mappingId/disable`：停用映射。
- `POST /preview`：开始后台生成预览，立即返回 `jobId`，不写入乐天。
- `POST /execute`：提交当前用户未过期的 `previewId`，立即返回 `jobId`，后台重新复核并执行。
- `GET /jobs/:jobId?page=1`：限任务所属用户、所属店铺查看进度；预览50行分页，返回全量变更数、归零数和有效期。
- `GET /jobs/:jobId?page=1&filter=changed`：筛选预览，filter支持all、changed、zero；返回完整计划数和筛选结果数。
- `POST /check`：只读连接检测，不验证或执行库存写入。
- `GET /issues?page=1`：店铺异常SKU待处理列表，50行分页。

## 每日刷新、补跑与任务诊断

- 每天17:30从首个搜索游标重新读取清单，结束遗留的未完成读取任务。手动点击读取仍可恢复本次中断游标；每日任务不复用昨天的半份清单。
- 17:45提供一次有限补跑。按日本日期读取每个店铺的持久化记录：只补跑当天未开始、或明确在写入前失败的店铺，包含17:30主任务在内最多两次。成功、部分完成、正在运行、中断待检查及写入结果未知的任务均不自动重放。没有再次开启任何已关闭的总开关或店铺开关。
- 每个店铺重新计算初始库存，不复用前一店铺的计算结果。写入前仍重新读取库存和预占；订单新鲜度、归零及范围骤减保护继续生效。
- 小批写入的预占查询限制到目标产品、材料及使用同一库存池的父产品。大范围整店计算仍使用一次分页汇总，避免拆批导致重复扫描及改变共享材料扣减顺序。Amazon/手工订单的旧格式产品ID覆盖保留保守查询兜底，不以缓存替代最新复核。
- 确认同步逐块解压旧预览并比较新计划，避免同时持有两份解压后的完整计划；保留旧格式预览兼容。压缩保存和页面分页不变。
- 进度接口提供开始时间、服务端时间、最近续约心跳和本进程最近阶段进展。阶段耗时、RSS、堆内存及外部库存请求耗时/重试次数写入日志；不记录API密钥和响应正文。
- 冲突提示和库存配置可查看当前占锁任务及心跳。只读连接检测不获取写入锁，也不触发中断写入恢复。检测和写入共享串行限速队列；库存写入仍保持跨进程互斥。
