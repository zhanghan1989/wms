# Xiya 运单同步：动态店铺名单

更新日期：2026-10-14。实现位置：`apps/api/src/orders/orders.service.ts`。

本文说明本次代码修改的行为；生产调查报告中 `6ee1fb4` 的固定名单属于修改前版本。是否已在生产启用，需以该修改的部署结果为准。

## 名单来源与更新

每次自动或手动同步开始时，WMS 从店铺设置读取最新名称、平台和启用状态，不缓存到下次任务。仅启用状态 `status=1` 的店铺进入当前名单。

- 新增并启用店铺：下次同步自动包含该名称。
- 修改店铺名：下次同步自动使用新名称，一般旧名称退出当前名单。
- 停用店铺：下次同步不查询或接受该配置名称。
- 一次任务只读取一份店铺快照，请求参数与返回匹配共用它；任务执行中修改设置会在下次任务生效。
- 没有启用店铺时，不调用 Xiya，避免空参数触发对方默认店铺查询。

店铺平台决定 WMS 订单来源，不从店铺名称猜测平台：

| 店铺平台 key | WMS 同步来源 |
| --- | --- |
| `amazon` | 亚马逊订单 `amazon` |
| `rakuten` | 乐天订单 `rakuten` |
| 其他自定义平台，包括 TikTok | 手动订单 `manual` |

因此当前已启用的 `DGAZ Store亚马逊日本` 和 `DGAZ Tiktok日本` 都会自动加入。

## 历史兼容名称

历史 Xiya 店铺名可能与 WMS 当前店铺名不同，特别是 WMS 的 `乐天-1号店` / `乐天-2号店` 与 Xiya 的 `DGAZ乐天日本`。为保留原有物流同步，存在启用的相应平台时，额外保留以下兼容名称：

```text
DGAZ乐天日本 → rakuten
DGAZ亚马逊日本站 → amazon
ArcDiary亚马逊日本站 → amazon
```

若某个历史名称已经在店铺设置中登记，完全以其配置的平台和启用状态为准；显式停用的历史名称不会因兼容逻辑被重新加入。这三个固定名称是历史兼容别名，新增或修改普通店铺无需维护代码。

WMS 设置中的当前名称应与 Xiya 返回的 `store_name` 一致。此修改自动跟随 **WMS 店铺设置**，不会从 Xiya 创建或改名 WMS 店铺，也不会自动推送 WMS 改名到 Xiya。

## API 与匹配规则

接口地址、密钥、`company_name`、`days=5` 和每天日本时间 18:00 的执行计划沿用原配置。变化是 `storeName` 由本次动态名单的全部名称用英文逗号连接；返回 `store_name` 使用同一名单确定来源。

订单仍按 `sales_order_id` 匹配，继续只写入符合中国发资格且没有运单的明细，不覆盖已有单号。TikTok 的更新数量计入 `manualUpdatedCount`。单号字段优先级仍沿用原实现，本次未调整。
