# 多中国公司与日本海外仓权限

## 数据归属

中国公司是数据隔离边界，公司下可以建立多个品牌。品牌名称在公司内唯一，不同公司可使用相同名称。产品、SKU、店铺、订单、库存、入出库、补货、退货、盘点、打印作业和操作日志均带公司归属。

现有数据通过迁移统一归入 ID 为 1 的“XYJG”。迁移同时将历史产品中的品牌名称补入这家公司的品牌字典。可以在用户管理中将默认公司改为实际名称。

产品 ID、店铺名称、箱号以及现有业务单号继续保留全局唯一规则，便于共用仓库扫码识别。此次不支持不同公司复用同一个产品 ID 或箱号。货架作为仓库设施共享，箱子与箱内库存按公司归属；不同公司的商品不能放入同一箱子。

## 人员权限

- 中国公司人员：只能访问自己的公司，操作权限继续由原有角色决定。
- 自动处理中心：海外仓可查看和处理订单、回传、邮件任务及库存同步，继续要求选定公司后执行业务写入。店铺选择使用只含连接 ID、店铺名称和业务开关的专用查询；不开放连接凭证、SMTP 配置、店铺授权和邮件模板管理。
- 手动订单参考资料：海外仓可读取店铺列表和平台列表（`GET /shops`、`GET /shops/platforms`），以生成、编辑订单；不开放平台／店铺的新增、修改、删除，也不开放平台连接凭证。
- 海外仓人员：所属公司显示“日本海外仓”（共享仓储组织，不是中国业务公司），内部沿用 `overseas_warehouse` 权限标记，可查看所有公司的仓储业务。处理业务前在顶部选择公司，单据、库存和日志归到所选公司。岗位操作权限仍由角色决定；需要管理者权限的仓储操作，应分配管理者角色。
- 系统管理员：无所属公司，管理公司、账号与全局配置，可以跨公司查看；处理具体业务前也需选择公司。
- 只有系统管理员可以授予海外仓或系统管理员权限。海外仓账号不能管理中国公司的员工、公司资料、平台密钥和全局备份。
- 只有系统管理员可以设置或调整员工所属公司；调整后旧会话失效，历史业务记录仍保留原公司归属。

公司禁用后，该公司的中国员工无法继续使用现有会话，海外仓也不能选择该公司作业。系统管理员仍可管理和重新启用公司。

## 使用顺序

1. 执行迁移并更新 Prisma Client，部署对应代码。
2. 系统管理员进入“用户管理 → 中国公司管理”，修改默认公司名称，并新增其他公司。
3. 在顶部选择公司，再进入现有品牌管理、店铺管理配置资料。导入产品前先建立对应品牌。
4. 新增员工时选择所属公司与角色，不再单独设置作业身份。新账号沿用原有激活流程。
5. 给日本仓人员选择“日本海外仓”所属公司。可用“全部公司”查看仓储业务；处理业务时切换到具体公司。

公司选择存放在每个账号独立的浏览器会话存储中，切换后重新载入页面，清除上一家公司页面中的选择状态。请求使用 `X-Company-Id` 携带选择；服务端独立验证访问权，不信任前端筛选。中国员工伪造其他公司的请求头会被拒绝。

## 平台同步、外部接口与缓存

平台连接归属于店铺公司；Amazon 和乐天的定时任务在各个启用的公司范围内依次执行，快照、订单与库存回传沿用该范围。各公司的乐天调度控制独立保存。库存看板、店铺看板、导出选项和逾期订单缓存也按公司隔离或在公司请求中重新查询。

喜亚接口保留现有共享密钥及上游参数，作为所有公司的共用对接通道，不绑定公司 1。产品同步统一执行并保留已有产品的公司归属；新产品按已配置品牌的唯一公司归属进入，未知品牌沿用 XYJG，跨公司重名品牌需先明确产品归属。喜亚推送订单按已有产品和店铺归属入账，出口库存、订单拉取及回执可跨公司处理。WMS 的普通员工接口仍按公司隔离。

公司管理入口仅系统管理员可见；原“部门管理”入口调整为“公司管理”。用户列表和表单只显示所属公司与角色，移除作业身份。现有工厂账号保留 XYJG 归属；日本海外仓账号和系统管理员的中国业务公司 ID 为空。

日本仓打印代理保留其专用机器密钥，负责领取所有公司的仓储打印任务；机器密钥不应发放给中国公司的业务员工。

## 迁移与验证

新增迁移：`apps/api/prisma/migrations/20261104100000_company_isolation/migration.sql`、`apps/api/prisma/migrations/20261104110000_user_company_affiliation/migration.sql`。迁移包含多张业务表的归属列、索引与外键，发布前按现有备份流程备份，并为大表结构变更安排维护窗口。不要运行 seed 覆盖正式环境账号密码。

```sh
npm run -w api prisma:generate
npm run -w api prisma:migrate:deploy
npm run -w api build
npm run -w api lint
npm run -w api test
```

MySQL 隔离集成测试仅在显式指定专用临时数据库时执行。该数据库需先具有最新结构，禁止使用正式数据库：

```sh
WMS_COMPANY_TEST_DATABASE_URL='mysql://test_user:test_password@127.0.0.1:3306/wms_company_test' \
  npm run -w api test -- --runTestsByPath test/company-isolation.integration.spec.ts
```

测试验证列表、ID 查询、聚合、共享货架关联、批量修改、跨公司关联、原生 SQL、事务中新建关联、海外仓跨公司查询及并发请求隔离。全局请求拦截器测试另覆盖伪造请求头、禁用公司、海外仓管理权限和喜亚共享接口身份验证。

## 本次生产发布的备份门禁

正式发布脚本在首次应用本次账号归属迁移前暂停 API 写入，生成完整 SQL 压缩备份（含触发器、存储过程和事件），记录 SHA-256，并在无网络、无生产数据卷的临时 MySQL 容器中完整恢复。所有原表的行数和 CHECKSUM TABLE EXTENDED 校验值必须一致，才允许进入迁移。备份保存在服务器用户主目录的 `.wms-pre-migration-backups/company-affiliation-*`，目录权限 700、文件权限 600，不上传到 GitHub。

迁移后、API 恢复前再次核对原表记录数、库存总量及所有历史业务归属，确保业务公司归属没有变化。仅海外仓账号与系统管理员解除中国业务公司的绑定，中国公司员工保留原公司。备份和恢复校验失败会恢复原 API；迁移后验证失败则将空账号／账号审计归属恢复为旧版兼容值后，尝试恢复原 API 镜像，保留完整备份及验证记录。不要使用 seed 迁移正式账号。
