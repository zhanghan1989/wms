# 多中国公司与日本海外仓权限

## 数据归属

中国公司是数据隔离边界，公司下可以建立多个品牌。品牌名称在公司内唯一，不同公司可使用相同名称。实物产品和库存唯一归属一家中国公司，两家公司不会有同款产品。亚马逊店铺、销售 SKU 和订单按中国公司隔离；乐天店铺、销售 SKU、组合商品及自动处理中心由日本方统一管理。同一产品的乐天与亚马逊销售共用原有实物库存。

现有数据通过迁移统一归入 ID 为 1 的“XYJG”。迁移同时将历史产品中的品牌名称补入这家公司的品牌字典。可以在用户管理中将默认公司改为实际名称。

产品 ID、店铺名称、箱号以及现有业务单号继续保留全局唯一规则，便于共用仓库扫码识别。此次不支持不同公司复用同一个产品 ID 或箱号。货架作为仓库设施共享，箱子与箱内库存按公司归属；不同公司的商品不能放入同一箱子。

## 人员权限

- 中国公司人员：管理本公司产品、亚马逊 SKU 和店铺，查看和下载本公司库存，通过手动导入或手动订单处理亚马逊业务，并处理分配给本公司的中国发货明细。SKU 列表、商品详情关联 SKU、全部 SKU 与未匹配 SKU 下载均排除日本方店铺的 SKU。乐天订单处理入口向中国公司开放，列表及详情仅显示本公司产品的乐天订单。涉及批次作业的海外仓订单处理出口继续隐藏。组合商品、API导入、自动处理中心及批量管理仍由日本方统一管理。备货、入库、日本仓出库、盘点和库存调整由日本海外仓处理，前端隐藏入口，后端拒绝直接调用。原有角色权限继续执行。
- 中国公司可查看日本乐天看板和导出销售 Excel。统计在聚合前按产品归属过滤，包括销售额、销量、订单数、环比、趋势及 SKU 排行。普通产品按产品所属公司归集，组合商品只在全部组成产品属于该公司时计入。同一订单含两家公司商品时，只计入本公司商品已分摊优惠券的净销售额，不计入整单金额。未匹配及混合归属组合不计入中国公司的销售数据。中国公司不显示工厂备货建议和全店同步条数；店铺连接、自动处理及工厂备货导出仍由日本方管理。
- 返品管理位于“订单处理 → 订单检索”下方，默认仅显示操作及检索区域，点击“展开返品一览”加载列表，检索后自动展开结果。中国公司账号仅可查看和检索本公司的返品，隐藏新增、导入、删除及勾选操作，后端拒绝写入请求；日本海外仓可查看和管理所有公司的返品，不受业务公司选择影响。列表和检索建议均由后端执行公司隔离。
- 日本海外仓：所属公司显示“日本海外仓”，按更新前的员工／管理者角色权限访问功能，不再使用“仅仓储业务”的路由白名单。组合产品、店铺看板、品牌／店铺资料、平台连接及自动处理中心设置／模板不因海外仓身份额外受限；原有接口角色权限继续执行。
- 海外仓不显示业务公司选择框，不受该选择框或旧请求头过滤；可直接查看、操作所有公司的业务。已有数据保留原公司归属；新记录优先从关联商品、店铺等推断归属，无关联时默认归 XYJG。乐天组合商品属于日本方销售配置，可以引用两家公司的产品；实物产品和库存不会因此转移归属。同一张乐天订单可包含两家公司的商品，各商品明细分别确定中国履约公司。仓库入出库等实物单据仍保留原有公司一致性校验。
- 系统管理员：无所属公司，管理公司、账号与全局配置，可以跨公司查看；处理具体业务前也需选择公司。
- 只有系统管理员可以将其他公司的账号调整为日本海外仓，或授予系统管理员权限。海外仓账号不能管理中国公司的员工。日本海外仓管理者可以管理本仓普通员工；中国公司管理者可以管理本公司普通员工（新增、激活、编辑、禁用、删除及重置密码），不能跨公司操作、转移公司归属或授予管理者权限。日本海外仓的用户管理范围不受顶部业务公司选择影响。
- 只有系统管理员可以设置或调整员工所属公司；调整后旧会话失效，历史业务记录仍保留原公司归属。

公司禁用后，该公司的中国员工无法继续使用现有会话，海外仓新建或修改业务记录时仍校验目标业务公司的启用状态。系统管理员仍可管理和重新启用公司。

## 使用顺序

1. 执行迁移并更新 Prisma Client，部署对应代码。
2. 系统管理员进入“用户管理 → 中国公司管理”，修改默认公司名称，并新增其他公司。
3. 在顶部选择公司，再进入现有品牌管理、店铺管理配置资料。导入产品前先建立对应品牌。
4. 新增员工时选择所属公司与角色，不再单独设置作业身份。新账号沿用原有激活流程。
5. 给日本仓人员选择“日本海外仓”所属公司。日本仓无需选择业务公司，即可访问所有公司业务。

中国公司和系统管理员的公司选择存放在每个账号独立的浏览器会话存储中，切换后重新载入页面，清除上一家公司页面中的选择状态。请求使用 `X-Company-Id` 携带选择；服务端独立验证访问权，不信任前端筛选。中国员工伪造其他公司的请求头会被拒绝。

## 平台同步、外部接口与缓存

Amazon 连接和定时任务继续按启用的中国公司执行。乐天订单、库存和销售任务由日本方统一执行一次，读取所有乐天连接以及各产品已有库存；系统管理员顶部的中国公司选择不缩小乐天中心范围。乐天任务开关与库存锁沿用原自动处理中心（历史存储键 companyId=1），不为每家中国公司生成新中心。已有乐天配置记录的 company_id 作为兼容存储信息保留，不作为商品货权或中国履约归属。

乐天订单新增 fulfillment_company_id，按现有产品解析规则（非空 sku_code 优先，否则 set_component_sku_code）匹配唯一产品的所属公司。历史订单在迁移中回填，新导入或改绑商品时同步更新；无法匹配的订单保持未分配，由日本方核实，不默认派给 XYJG。中国订单列表、详情、更新、导出和原生查询按履约公司隔离，订单详情保留原有完整字段。日本海外仓可查看和处理全部。

转中国发货保留现有自动缺货分派、手动切换及切回日本发的状态校验和权限。手动切中国发不直接扣减账面库存，拣货明细移除后解除对应占用，账实差异另行处理。喜亚推送 API 和协议本次不调整。

产品详情展示实物在库数、总占用和可用数量。库存计算包括本产品的 FBA、日本拣货和未入拣货批次的待发订单，沿用现有去重规则。中国公司只能查询自己产品的汇总数量；乐天与亚马逊不会各复制一份实物库存。其他库存看板、导出选项和逾期订单缓存继续按公司隔离或在公司请求中重新查询。

喜亚接口保留现有共享密钥及上游参数，作为所有公司的共用对接通道，不绑定公司 1。产品同步统一执行并保留已有产品的公司归属；新产品按已配置品牌的唯一公司归属进入，未知品牌沿用 XYJG，跨公司重名品牌需先明确产品归属。喜亚推送订单按已有产品和店铺归属入账，出口库存、订单拉取及回执可跨公司处理。WMS 的普通员工接口仍按公司隔离。

店铺管理列表中 Amazon 店铺显示所属中国公司及连接所属公司，日本方店铺显示“日本海外仓”。系统管理员选择某家中国公司时，仍可管理日本方共用店铺及销售 SKU。

中国公司普通员工和管理者均可查看本公司的 Amazon SP-API 连接、发起授权及续期、保存连接设置、测试连接、执行单店同步及查看同步记录。连接入口在店铺管理中保留，所有操作沿用公司隔离；全店批量拉取及全局覆盖统计继续执行原有管理者权限，日本海外仓普通员工的 Amazon 连接权限保持原限制。

公司管理入口仅系统管理员可见；原“部门管理”入口调整为“公司管理”。用户列表和表单只显示所属公司与角色，移除作业身份。现有工厂账号保留 XYJG 归属；日本海外仓账号和系统管理员的中国业务公司 ID 为空。

日本仓打印代理保留其专用机器密钥，负责领取所有公司的仓储打印任务；机器密钥不应发放给中国公司的业务员工。

## 迁移与验证

新增迁移：`apps/api/prisma/migrations/20261104100000_company_isolation/migration.sql`、`apps/api/prisma/migrations/20261104110000_user_company_affiliation/migration.sql`、`apps/api/prisma/migrations/20261105120000_rakuten_fulfillment_company/migration.sql`。最新迁移只新增乐天履约归属及其回填，不修改实物库存、原有公司归属或喜亚接收状态。部署新代码前必须先完成迁移。发布前按现有备份流程备份，并为大表结构变更安排维护窗口。不要运行 seed 覆盖正式环境账号密码。

```sh
npm run -w api prisma:generate
npm run -w api prisma:migrate:deploy
npm run -w api build
npm run -w api lint
npm run -w api test
```

MySQL 隔离集成测试仅在显式指定专用临时数据库时执行。该数据库需先具有最新结构，禁止使用正式数据库：

```sh
WMS_COMPANY_TEST_DATABASE_URL='mysql://test_user:test_password@127.0.0.1:3306/wms_company_test' \
  npm run -w api test -- --runTestsByPath test/company-isolation.integration.spec.ts
```

测试验证列表、ID 查询、聚合、共享货架关联、批量修改、跨公司关联、原生 SQL、事务中新建关联、海外仓跨公司查询及并发请求隔离。全局请求拦截器测试另覆盖伪造请求头、禁用公司、海外仓管理权限和喜亚共享接口身份验证。

## 本次生产发布的备份门禁

正式发布脚本在首次应用乐天履约归属迁移前暂停 API 写入，生成完整 SQL 压缩备份（含触发器、存储过程和事件），记录 SHA-256，并在无网络、无生产数据卷的临时 MySQL 容器中完整恢复。所有原表的行数和 CHECKSUM TABLE EXTENDED 校验值必须一致，才允许进入迁移。备份保存在服务器用户主目录的 `.wms-pre-migration-backups/company-affiliation-*`，目录权限 700、文件权限 600，不上传到 GitHub。

迁移后、API 恢复前再次核对原表记录数、库存总量及所有历史业务归属，并验证乐天履约公司与对应产品一致、未匹配产品保持未分配。备份和恢复校验失败会恢复原 API；迁移后验证失败则尝试恢复原 API 镜像，保留完整备份及验证记录。只有同时首次执行旧版账号归属迁移时，回滚才恢复旧客户端所需的账号／账号审计归属兼容值；本次仅执行乐天履约迁移时，不改写现有日本海外仓和系统管理员的账号归属。不要使用 seed 迁移正式账号。
