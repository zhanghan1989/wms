# 日本发订单完整流程

适用于同一店铺、同一RMS连接的纯日本发订单。自动处理资格为日本时间2026年10月1日00:00起首次导入WMS；按订单全部明细的最早创建时间判断，补加明细不改变资格。中国发、日中混发按各自流程处理。

## 一条订单流程、三个独立结果

正常顺序：API导入 → 新規受理通知 → 仓库拣货、制单、打印 → 点击5确认作业完成及实际出货 → 单号回传乐天 → 日本発发货通知。

分别记录新規邮件、单号回传、日本発邮件。新規未发送不阻止仓库作业，但禁止单号回传；日本発必须同时满足出货确认、回传完成以及新規已发送/人工忽略。仅有单号、打印记录或邮件记录，不能推断其他步骤已经完成。

## 1. API导入

- 默认全天每20分钟、日本时间执行统一流程：导入及立即处理新規 → 物流同步 → 单号和后续邮件。日本发没有清关或签收前置条件；共享物流查询主要服务中国侧。
- 只查询乐天状态300（待发送）订单。首次回查7天，后续从上次成功同步时间向前重叠6小时，避免查询窗口边界遗漏。
- 乐天状态300不代表WMS未删除。系统内逻辑删除的订单可能继续由API返回，但永久排除记录阻止重导。
- 多商品/组合拆分保存明细，同订单只保存一条新規任务。更新已有订单、认领既有CSV、补加商品明细不会重发已经完成的新規。
- 订单、导入记录及新規任务在同一事务保存。提交失败不发送；提交成功后只处理本次新增订单的新規，不等物流和单号。
- 定时导入、人工预览确认导入、“立即检查”共用正式导入逻辑。预览只读取、展示，不发送邮件。
- 导入成功后的邮件失败不回滚订单，不把导入记录改成失败。保留任务交定时补查。

## 2. 新規邮件

新規是固定受理通知，允许买家姓名、订单号、签名变量，不包含订单商品、数量、金额、分仓或物流信息。店铺必须启用实际模板版本；缺模板不自动采用默认文案。默认文案仅供管理员编辑、预览和明确启用。

普通订单、人工修改商品、完整或不完整组合、首次同步、长时间后恢复同步，都不要求逐单正文确认。商品相关变更提醒不阻止这封固定通知。预览一致性只核对订单号、买家姓名和收件邮箱，商品或单号变化不会让新規预览失效。

发送仍需店铺启用、邮件通知开启、自动发送未暂停、店铺邮件功能未异常暂停、可用的乐天买家匿名邮箱、有效SMTP配置以及合规启用模板。通知关闭期间保存待发任务，重新开启后按正常条件处理，不额外加历史邮件内容确认。

发送前再核实乐天返回目标订单号及状态。查不到目标、返回其他订单或网络查询失败时等待20分钟，不消耗SMTP发送次数；新規已离开300、状态异常时停止并转人工核对，不自动删除订单。模板异常由管理员修正一次，不是逐单确认商品内容。

成功保存邮件结果后不再自动发送本事件。确实需要人工发送时从处理中心预览并发送固定正文，不能逐单改成商品说明。

## 3. 仓库拣货、面单与实际出货确认

仓库按正常批次作业拣货、确认数量、导出Yamato资料、上传PDF并扫码打印。上传PDF会登记物流公司、单号及登记时间；这只是制单资料，不能证明实际出货。

完成实际出货后点击“5.确认本批次作业完成及出货”，并确认提示。服务器检查：

1. 批次存在，处于Yamato已导出或已完成状态。
2. 对应Yamato批次已上传PDF，面单数大于0，全部面单已有打印确认。
3. 没有待完成的打印或补打任务。
4. 日本侧来源明细实拣数量覆盖其请求数量，批次有单号。
5. 当前未删除订单仍属日本侧；当前单号与批次单号一致，订单数量没有超过实拣数量。

满足条件后在同一事务记录批次作业完成时间/操作人及日本侧明细的仓库出货确认时间/操作人。确认已存在时保留原时间和操作人，重复点击不会产生另一份出货确认。未删除且单号匹配的日本明细才会更新，中国侧、已删除或不匹配的明细不被认定已出货。

同订单分多个批次/包裹时，需要全部日本明细确认。少一条确认，即使其他包裹已制单或完成，也不自动回传整单和发送日本発。

旧批次只有完成状态、没有新出货确认时间时，不用更新时间、单号登记时间或打印时间估算。页面允许仓库核实后重新点击5确认。旧已完成邮件和回传记录保留，不能因此重复发送。

点击5保存确认后，由下一轮20分钟任务检查回传和邮件；也可在处理中心“立即检查”或逐项执行。这个按钮本身不直接调用乐天或SMTP。

## 4. 单号回传

须启用单号回传功能、店铺没有异常暂停，订单未逻辑删除、没有未解决业务变更，且所有日本侧明细均有仓库出货确认、单号、登记日期、明确乐天送付先ID和可识别物流公司。

按乐天送付先ID分组，同送付先的相同单号去重，不同包裹分别回传。发送给乐天的発送日是日本时间的仓库确认出货日，不使用提前制单的登记日。未知物流公司直接报错，不能猜成Yamato。

回传前getOrder必须返回明确匹配的订单号。号码尚未回传时必须仍为300；其他状态停止自动回传，交人工核对，不据此自动删除。

请求前持久记录请求时间及包裹指纹：

- 乐天还没有号码：发起回传，成功保存单号完成结果及唯一日本発任务。
- 重试时乐天已有号码，并与本系统已保存的同一请求相符：确认回传完成，不重复请求。
- 乐天已有号码，无法关联本系统请求：记录“已核实已有单号”，日本発进入发送情况待确认，不推断外部已经发送或尚未发送。

邮件通知关闭时仍保存日本発任务，开关只决定是否发送。单号回传不是邮件发送；忽略回传也不能当成已经核实回传完成。

已完成后包裹号、物流公司、仓库确认日期或发货范围发生变化，转人工核对。不会自动覆盖历史回传或重发历史邮件。人工修正后重试仍执行相同出货、资料和乐天状态检查。

## 5. 日本発邮件

前置条件：全部日本侧明细已确认出货、全部包裹资料齐全、回传成功或经过明确核实、新規已经发送或人工忽略，且订单未逻辑删除、没有未解决业务变更。

回传成功后保存日本発任务，正常在该轮邮件阶段发送。通知关闭或暂停时保持待处理。之前已经发送的同事件不重复生成或重发。

此邮件含订单/商品、配送与物流信息：结构化内容完整时自动生成；特殊说明、人工修改数量/SKU导致原购买信息不一致、组合信息不完整时，需人工预览并修正正文。仅因“人工修改过”或“组合订单”标签不会强制确认。预览绑定模板版本、完整订单事实及改后的正文，发送前变化必须重新预览。

发货通知使用全部日本包裹及仓库确认出货日期。已删除用单号登记日或当天补出発送日的旧兜底；缺少有效出货日期直接阻止生成。不会因系统看到一个单号就告知整单已发货。发送前核实乐天订单，不要求仍为300，因为正常回传后乐天状态可能已经推进；取消相关或无法识别状态仍暂停核对。

若历史结果已有回传但缺少日本発任务，属于数据/发送记录异常：人工核实后明确补建或确认无需发送；不自动猜测补发。认领CSV后缺新規任务同样需核实历史发送记录。

## 6. 失败、不确定、忽略与取消

| 情况 | 行为 |
| --- | --- |
| 尚未确认出货或资料缺少 | 等待条件，不消耗尝试次数 |
| 查询乐天失败/返回不匹配订单 | 不发送；下轮核实 |
| 明确接口/SMTP临时失败 | 按退避时间重试，定时到期检查，最多10次 |
| SMTP可能已经接收，但响应中断或成功状态保存失败 | 记发送结果不确定，停止自动重发；人工核实后确认完成或明确重发 |
| 执行者失联，发送已开始且超过30分钟未完成 | 转结果不确定；不直接重新发送 |
| 认证/配置异常 | 暂停对应店铺环节，管理员修复并明确恢复 |
| 达到重试上限/参数或收件人错误 | 转人工处理 |
| 人工忽略新規 | 本邮件不发送，允许后续日本発继续；不等于取消订单 |
| 人工取消新規 | 日本発停止，不能无限等待后自动发送 |
| 人工重试单笔任务 | 只恢复该笔，不清除整个店铺的异常暂停 |
| 人工逻辑删除订单 | 全单后续操作终止；已完成和结果不确定记录保留为证据 |

“已发送”表示SMTP明确接受买家地址并成功保存结果，或经过人工确认的完成记录；不表示买家已阅读，也不是承运商送达证明。Message-ID是追溯信息，不能保证邮件服务器跨系统自动去重。

## 7. 人工取消订单与已删除路径

同一订单号按产品明细导入。用户勾选产品后点击“批量删除”，后台读取整单所有未删除产品逐单判断：勾选部分产品时只删除勾选产品并记录商品级永久排除，其余产品继续处理，后续商品邮件要求人工确认正文；勾选全部未删除产品时按整单永久排除，终止未完成回传和全部邮件。判断包含其他分页和筛选外的产品。保留删除时间、操作人和历史证据；API/CSV重导及同步回滚不能恢复已删商品。不由客户状态或API状态自动删除。

正在回传/发送的店铺通过执行锁拒绝删除，不能把已经发生的外部动作撤回。关联拣货批次的订单先由仓库处理。删除只影响本系统，不自动取消乐天订单或向外部仓库发取消消息。

CSV备用回传路径已整体删除，包括处理中心下载入口、回传文件生成接口，以及当日邮件用CSV。日本发单号统一由处理中心通过API回传。订单CSV导入仍保留。

## 8. 界面、容量与部署

处理中心提供人工事项、处理中、处理记录、店铺设置。显示状态与实际执行共用同一判断；移除隐藏旧手工清单、独立全店同步入口、独立店铺自动运行入口及重复状态计算。任务整理只准备本地任务并遵守店铺锁，不回传或发信。

每20分钟是检查节奏，不保证每轮完成全部积压。默认每店回传50个任务、邮件100个；导入后新規按100个订单分批；候选/人工异常队列轮转，避免前排阻塞。当前每个订单明细只能保存一个单号，多包裹通过不同明细/送付先表达。

自动导入和发送默认关闭/暂停，源码修复不改变线上开关。本次未部署或执行真实订单操作。上线前执行软删除、废弃新規确认标记清理、仓库出货确认三项迁移；旧已发送、结果不确定或人为取消邮件不重置，旧完成批次不自动推测出货时间。

## 执行安全规则（2026年10月13日确认）

混发只回传中国侧；已有回传按送付先及单号核实，不新增物流公司/日期匹配要求。所有回传必须等待新規已发送或明确人工忽略。失锁或心跳失败停止后续外部操作；已在途操作无法撤回。SMTP必须明确接受买家地址，只有BCC成功不能记客户邮件成功。领取邮件任务后重新核对逻辑删除、业务变更、发货类型、出货/清关、回传及前置邮件条件，并核对人工预览事实。运行记录超过30分钟但执行锁心跳仍有效不判中断；失联后才恢复超时任务，已开始SMTP的任务转结果不确定。


## 多包裹拆分

超过单包尺寸时，工作人员将部分商品的内部订单号改为原号+A/B；独立保存原乐天订单号。仓库分别打印及确认各包裹，系统等待全部日本侧包裹就绪，再对原乐天订单汇总回传每个快递单号。新規、日本発邮件共用原订单的一套任务，正文包含全部包裹。删除范围也按原订单计算，包含拆包产品。详见[原订单与人工拆包规则](rakuten-order-workflow.md#手工拆包与原乐天订单2026年10月14日)。
