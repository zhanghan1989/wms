# WMS 逻辑问题修复记录

对应 [逻辑审查与优化方案](LOGIC_REVIEW_2026-09-22.md) 的前七项，修复日期：2026-09-23。

## 已完成

1. 用户管理接口限制普通管理员授予、修改高权限角色，也禁止修改自己的角色、部门和状态。JWT 每次验证当前账号状态、角色、会话版本和会话记录；退出、改密、重置密码、MFA 启用以及账号权限变更会撤销旧会话。
2. 库存写入统一按产品锁定，扣减使用条件更新，关键事务在死锁后重试。FBA 补货单状态转换加锁，出库流水加业务幂等键；重复提交不会重复扣库存。
3. FBA、海外仓拣货和 BOM 材料统一计算可用库存。创建与确认时重新检查预占，手工扣减和移箱也检查现有承诺。
4. 批量入库明细保存实收数量、确认人及差异原因；实收零件数也保留确认事实。产品维度调整、普通/批量入库、移箱与主要出库入口在库存事务中记录流水。

## 数据库部署与历史数据

部署前备份数据库，并依次应用 `20260922140000_auth_sessions`、`20260922141000_inventory_receipts_ledger` 两个迁移，再部署使用新字段的服务。部署后所有旧 JWT 会因为缺少会话编号而失效，用户需要重新登录。

历史批量入库的 `actual_qty` 保持 `NULL`，表示无法仅凭应收数量确认实收数量；不要把 `qty` 批量复制到 `actual_qty`。历史上缺失的库存流水也不能从当前余额自动重建。应使用历史审计及单据逐项核对，再决定是否补录。此代码未执行生产库迁移或历史数据回填。

本仓库早期迁移链在全新空库上存在基线依赖问题：第一条迁移引用尚未创建的 `users` 表。此次隔离验证使用当前旧版 Prisma schema 初始化测试库，再应用上述两条新迁移。正式环境若已有完整迁移历史，可在备份后按原有部署流程应用；全新安装需要先修复历史基线链，不能直接在空库执行全部迁移。
