## 已实施

| 问题 | 当前处理 |
| --- | --- |
| 同商品、同姓名导致错误 PDF 匹配 | 必须包含完整订单号，并匹配全部成品 ID 和收件人；不再仅凭商品与姓名自动绑定。无法读取订单号的 PDF 会被拒绝，需要调整导出模板。 |
| 快递单号取到商品 ID 等号码 | 优先识别快递单号字段；无字段时只接受唯一候选，并排除当前已知产品、订单号码。多候选及批次内重复单号会阻止上传和回写。 |
| 代理未提交就能确认打印完成 | 待领取任务不能确认已出纸；必须有提交回执或进入结果核对流程。取消待领取任务使用条件更新，避免与代理领取竞争。 |
| 不同工位或不同装包请求复用任务 | 保存操作员、工位和请求编号；同一请求重试复用原任务，其他请求不得接走任务。预览过滤其他工位已有的活动打印任务。 |
| 任务中断或页面刷新无法恢复 | 新增批次任务查看、出纸核对、异常恢复；当前浏览器标签页保存扫码进度、请求编号和待确认任务，刷新后点击“查看 / 恢复打印任务”恢复。关闭标签页后可从服务器找回已建立的任务，未提交的装包进度需重新核对。 |
| 原工位不可用 | 管理员可显式接管异常任务，记录原操作员、原工位、接管人和时间。接管停止自动执行、撤销旧领取令牌，并要求核对原纸张。未提交的代理任务接管后仍只能取消未出纸，不能直接认定已打印。 |
| 连续扫码被清空 | 先清除已接受的一笔输入，打印完成后不再清空后续输入；忙碌期间明确提示未计数并保留输入，包括下一次扫描与上一件为同一码的情况。 |
| 补打未结束仍能完成批次 | 同一事务中锁定面单页，检查未打印页与所有待处理打印/补打任务后再完成批次；使用最新已提交状态读取，避免等待锁后读到旧状态。 |
| 直打与代理打印机选择不同 | 直打也按商品配置选择打印机，保留全局默认配置作为兜底。 |
| 文件或网络等待无边界 | PDF 单文件限制 20MB、单次总量 100MB、最多 20 个文件、最多 2000 页；打印代理请求、下载及主要打印命令增加超时。请求编号支持没有 `randomUUID` 的浏览器。 |

## 业务规则

- 肩带成品码、肩带本体码是同一件肩带的替代识别方式，每件只扫一次；两种码的合计数量必须等于订单肩带数量。
- 共用本体对应多个订单或同订单多个成品时，需要选择具体订单/成品。
- 配件外箱码仍用于拣货。装包时配件没有独立条码，由操作员清点并输入准确数量。
- 面单括号中的本体和配件数量是成品总量对应的材料规格；装包材料确认按实际需要组装的数量计算。
- 提交给打印系统不等于实际出纸。出纸确认显示快递单号，要求核对纸张；原面单的首次打印时间不会被补打覆盖。

## 恢复操作

1. 点击“查看 / 恢复打印任务”，查看订单、快递单号、打印机及待处理状态。
2. 有提交回执的任务先核对原纸张，确认已出纸或先取消原打印队列后确认未出纸。
3. 领取后无回执的异常任务，至少等待五分钟，停止原打印程序并清空原队列后恢复；不会因超时自动重打。
4. 原工位无法使用时，由管理员按相同停止、取消及核对要求接管。条件更新防止任务状态变动时覆盖原任务，旧代理回报不能重新激活已结束任务。
5. 确认未出纸后保留扫码数量，可再次确认打印。恢复已出纸则完成原任务，不新建打印任务。

工位归属在打印任务建立时锁定。本轮没有增加“选定订单、尚未完成扫码时”的跨工位装包预占；两个工位可能同时预览尚无任务的同一订单，但只能有一个打印请求成功建立任务，另一请求会被阻止。
