# 亚马逊与 TikTok 运单号未同步调查

调查日期：2026-10-14。线上版本：`6ee1fb4ce078611982bb8e0aae14dc521c674110`。

本次读取生产配置、生产订单及 Xiya 物流导出响应，并调用线上原代码的标准化与资格判断方法复现过滤结果。未调用实际同步写入方法，未修改生产订单、代码或配置。本文时间为日本时间（UTC+9）；保留的接口原始时间字段自带 UTC+8 时区。

## 已确认原因

**WMS 运单自动同步的店铺名单没有包含 `DGAZ Store亚马逊日本` 和 `DGAZ Tiktok日本`。这两个店铺在 Xiya 已有运单，WMS 却在请求和返回处理两处漏掉它们。**

1. 请求 `storeName` 由代码中的固定名单生成，因此不查询这两个店铺。
2. 返回处理再次用同一名单精确匹配 `store_name`；不认识的店铺整条跳过。因此只扩大请求范围、不补充返回映射，仍无法同步。

目前固定名单只有：

```text
DGAZ乐天日本 → rakuten
DGAZ亚马逊日本站 → amazon
ArcDiary亚马逊日本站 → amazon
```

生产店铺设置中已存在 `DGAZ Store亚马逊日本` 和 `DGAZ Tiktok日本`，但运单同步没有从店铺设置动态获取名单。昨天提交 `4bba8e6` 处理了新亚马逊店铺名称与库存下载模板的匹配，没有修改运单同步名单；不能据此认为运单同步也已适配。具体改名操作的时间未在本次调查中核验。

## 修复范围与验收建议

最小修复是在同一店铺映射中补充：

```text
DGAZ Store亚马逊日本 → amazon
DGAZ Tiktok日本 → manual
```

保留原有店铺名以兼容历史记录。该映射同时生成请求名单和决定返回来源，需要同时验证两处行为。TikTok 进入 `manual` 来源后，现有手动订单匹配逻辑可以继续使用。

部署后执行一次正常同步，核对上表 7 笔订单的 8 条明细：预计本批次新增亚马逊运单 6 条、手动订单运单 2 条；实际总计数可能还包含其他店铺待同步记录。再次同步应不覆盖已有单号。补充有新旧店铺名、TikTok、多商品明细和已有运单的回归验证。

本次只完成调查与证据记录，尚未实施上述修复或回写运单。其他订单是否还存在日期窗口、字段含义或状态不符合的问题，不在这 7 笔样例的已确认结论内。
