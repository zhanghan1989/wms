重启恢复了服务，不代表长期问题已修复。未改动交换策略、数据库配置或实例规格；未自动重试发布。

## 建议优先顺序

1. 评估将实例内存提升至至少 4 GiB，为 MySQL、API、系统和发布过程留出余量；需另行决定费用和配置。
2. 检查 MySQL 实际缓存、连接数和峰值，制定内存预算，再设置合适参数，避免直接压低容器内存导致数据库被杀。
3. 检查 swappiness=0 的来源并评估交换策略，保留应急余量；swap 不能替代物理内存。
4. 发布增加内存/磁盘压力检查和单阶段超时；控制 git 自动整理与镜像导入重叠，避免失败时持续占用资源。
5. 记录进程内存、内存 PSI、磁盘等待与发布阶段，捕捉下一次峰值后再判断是否有应用泄漏。
