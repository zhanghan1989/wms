# Fulangke WMS · Amazon SP-API 安全与合规基线

文档所有者：乳山市弗朗克贸易有限公司
安全联系人：flachic0001@gmail.com
复审频率：每 6 个月及发生重大变更后
当前版本：2026-08-05

## 1. 适用范围

本基线覆盖 Fulangke WMS 官网、WMS 应用、Amazon Selling Partner API（SP-API）连接、阿里云 ECS/MySQL/Redis、GitHub Actions 部署链路以及获准的 XIYA/UOF 业务接口。首期 Amazon 应用只申请非受限的“库存和订单追踪”角色，不请求买家姓名、地址、电话或邮箱。

每个 Amazon 销售伙伴必须独立完成 OAuth 授权。系统店铺与 Amazon Seller ID 一一关联，不共享 Seller Central 登录凭证，也不跨店铺复用 Refresh Token。

## 2. 已实施控制

| 控制域 | 当前控制 |
| --- | --- |
| 传输安全 | 官网、WMS 和 OAuth 回调使用 HTTPS；WMS 返回 HSTS、`Referrer-Policy: no-referrer`、CSP、禁止 iframe 等安全响应头。 |
| OAuth | OAuth state 使用 256-bit 随机值、数据库仅保存 SHA-256 摘要、10 分钟失效、回调后原子消费；应用商店回跳仅允许 Amazon HTTPS 域名及确认路径。 |
| 店铺隔离 | OAuth 请求记录系统店铺和预期 Seller ID；回调双向校验，拒绝 Seller ID 重复绑定到其他系统店铺。 |
| 凭证保护 | Amazon Refresh Token 使用 AES-256-GCM 加密后保存；LWA 密钥、加密密钥和业务 API Key 仅由服务器环境注入，不返回浏览器。 |
| 网络隔离 | MySQL、Redis 和应用源端口绑定 `127.0.0.1`；公网仅开放反向代理所需服务；生产服务器使用阿里云安全组。 |
| 身份与权限 | WMS 使用唯一用户账号、bcrypt 密码哈希、JWT 会话和角色授权；Amazon 连接管理仅管理员可操作。 |
| 审计与恢复 | 系统保留关键业务操作、Amazon 同步运行和错误记录；数据库执行备份并支持恢复。 |
| 数据最小化 | `AMAZON_SP_API_INCLUDE_RECIPIENT=false`；首期只同步订单运营字段、商品字段和 FBA 库存。 |
| 依赖治理 | NestJS、Prisma 及其生产传递依赖已升级到当前同主版本安全补丁；`npm audit --omit=dev` 的其余高风险项仅为旧版 `xlsx`，已列入替换计划，不能标记为已解决。 |

## 3. 上线及提交 Amazon 前必须完成

以下项目完成前，不得在 Developer Profile 中声称已经实施：

1. 为所有 WMS 用户执行不少于 12 位、包含大小写字母/数字/特殊字符的密码策略，并启用 MFA；
2. 在 ECS 上轮换数据库、JWT、XIYA、UOF 以及所有曾写入代码或文档的密钥；
3. 使用独立数据库应用账号替代 root 连接，并确认最小权限；
4. 启用并核验阿里云安全中心主机防护、恶意软件检测、安全组和告警；
5. 完成一次备份恢复演练和一次安全事件桌面演练，记录日期、人员、结果和整改项；
6. 与 XIYA 等数据接收方确认授权范围、保密义务、删除要求和安全事件通知义务；
7. 建立账号权限半年复审、离职立即停权、密钥轮换和补丁管理记录。
8. 将无可用 npm 安全修复的旧版 `xlsx` 替换为受维护的工作簿解析方案；完成前限制上传大小、来源和权限，并将其保留在风险登记表中。

## 4. 权限与账号管理

- 用户必须使用个人唯一账号，禁止多人共享账号。
- Amazon 授权、用户管理、凭证配置和数据导出权限仅授予有业务需要的管理员。
- 新增或变更权限应由负责人批准并记录；员工离职或职责变化时应立即撤销不再需要的权限。
- 每 6 个月审查用户、角色、服务账号、API Key 和 Seller 授权记录。
- 连续认证失败、异常地点访问或异常数据导出应触发调查；高风险账号应立即停用并轮换相关凭证。

## 5. 变更、漏洞与供应链管理

- 所有代码变更通过独立分支、自动编译和测试后才能合入生产分支。
- 生产部署使用固定 Git 提交和构建产物；不得在服务器上直接开发。
- 每月检查操作系统、容器镜像及 npm 依赖安全更新；高危漏洞优先修复。
- 仓库及历史提交不得包含真实密码、API Key、OAuth 密钥或 Refresh Token。
- 第三方服务启用前评估其数据范围、安全能力、合同义务和退出/删除机制。

## 6. 证据留存

至少保存以下审核证据：权限复审表、密钥轮换记录、补丁记录、备份恢复报告、事件演练报告、GitHub Actions 测试结果、阿里云安全组及安全中心截图、第三方数据处理约定和 Amazon OAuth 端到端测试记录。
