# 生产主机安全基线

检查日期：2026-08-05

实例：阿里云 ECS（广州）

用途：Amazon SP-API 申请前安全证据与整改清单

## 已核验

| 项目 | 结果 |
| --- | --- |
| 操作系统 | Ubuntu 24.04.3 LTS，内核 6.8.0-90 |
| WMS 配置文件 | `/root/wms/.env` 权限 `600 root:root` |
| API、MySQL、Redis 容器 | 均设置 `unless-stopped`；MySQL 健康检查通过 |
| 应用实际绑定 | API、MySQL、Redis 分别绑定本机 `127.0.0.1:3000/3306/6379` |
| 公网监听 | 22、80、443；3000 仅由 Nginx 提供旧地址到生产域名的 308 跳转 |
| 外部端口抽查 | 20、21、888、8888、18933、39000、40000 均关闭或被安全组过滤 |
| 防火墙 | UFW 已启用；仅保留 22、80、443、3000 的 IPv4/IPv6 入站规则；历史 20/21、888、8888、18933、39000-40000 规则已于 2026-08-05 删除 |
| 自动安全更新 | `unattended-upgrades` 运行中 |
| SSH 暴力破解防护 | Fail2ban `sshd` jail 已启用并设为开机启动；10 分钟内失败 5 次封禁 1 小时；首次核验已产生有效封禁记录 |
| TLS | `wms.fulangke.cn` 使用 Let's Encrypt，有效期至 2026-11-03 |
| 自动续证 | `certbot.timer` 运行中 |
| 阿里云安全中心 | 控制台显示基础能力“防护中”，但漏洞修复、云安全态势管理、主机安全防护均未开启 |
| ECS 安全组 | 80、443、3000 向公网开放；历史 RDP 和全部 8888 规则已于 2026-08-05 删除；全网 SSH 暂时保留供 CI/CD 部署 |
| MySQL 管理账号 | root 密码已于 2026-08-05 轮换为随机 256-bit 值；旧默认密码验证已拒绝；应用继续使用仅限 `wms_v1` 的 `wms_app` |
| 公网默认站点 | 公网 IP 的 80 端口以 308 跳转到 `https://www.fulangke.cn/`；旧 IP:3000 以 308 跳转到 `https://wms.fulangke.cn/` |
| ECS 快照 | 0 个快照、0 个自动策略，快照服务尚未开通 |

## 申请前整改

| 优先级 | 发现 | 整改与证据 |
| --- | --- | --- |
| P0 | 未发现 WMS 数据库/文件的独立备份任务，控制台也显示 0 个快照、0 个策略 | 开通快照或加密 OSS 备份，至少每日执行；随后完成一次隔离恢复测试 |
| P0 | 云安全中心只有基础“防护中”，漏洞修复、态势管理和主机安全防护未开启 | 根据 Amazon 所填控制启用相应能力并归档控制台截图；未真正实施前表单必须回答“否” |
| P0 | 当前仍有 64 个可升级软件包 | 先创建快照，在维护窗口安装安全更新，重启后验证 WMS、OAuth、XIYA、打印 Agent 和证书 |
| P1 | SSH 22 既有两个指定 IP 规则，也存在 `0.0.0.0/0` 全网规则 | 已先用 Fail2ban 降低暴力破解风险；当前 GitHub Actions 使用动态出口通过 SSH 部署，仍需改为固定出口、阿里云 OOS/云助手或自托管 Runner，再删除全网 SSH |

端口 3000 暂时保留的唯一用途是兼容旧书签 `http://8.134.176.116:3000/`，其响应必须始终为到 `https://wms.fulangke.cn/` 的永久跳转，不能直接暴露 API。

本记录是内部核验，不替代每月认证漏洞扫描或年度独立渗透测试。
