Amazon 安全事件报告：使用 Amazon 当前 DPP 指定的事件报告渠道，并同时遵循 Developer Profile 表单当时显示的通知要求
复审与演练：至少每 6 个月一次

## 1. 事件范围

事件包括但不限于：Amazon 数据或令牌未经授权访问、凭证泄露、恶意软件、异常批量导出、越权、数据误发、生产服务器入侵、备份泄露、第三方处理方安全事件和无法解释的数据完整性变化。

## 2. 分级

- **P1 严重**：确认或高度怀疑 Amazon 信息、OAuth 凭证或生产管理权限泄露；立即响应。
- **P2 高**：生产服务被攻击、异常访问或关键控制失效，但尚未确认数据泄露；1 小时内响应。
- **P3 一般**：低影响漏洞、失败攻击或非敏感服务异常；1 个工作日内处理。

## 3. 响应步骤

1. **发现与记录**：记录发现时间、报告人、受影响系统、请求 ID、日志和初步影响，避免破坏证据。
2. **遏制**：停用涉事账号/连接、撤销 Seller 授权、轮换 LWA/Refresh Token/API Key/JWT/数据库凭证，隔离主机或阻断来源 IP。
3. **评估**：确定数据类型、店铺、时间范围、记录数量、外部接收方和攻击路径。
4. **通知**：如涉及 Amazon 信息，在发现后 **24 小时内**通过 Amazon 当前 DPP 指定的事件报告渠道报告；如 Developer Profile 表单同时指定其他地址或入口，也一并通知。按法律和合同通知受影响用户、监管机构及处理方。
5. **清除与恢复**：修补漏洞、清除恶意内容、从可信备份恢复、验证完整性并逐步恢复服务。
6. **复盘**：事件结束后 5 个工作日内形成原因、时间线、影响、处置、控制缺口和负责人明确的整改计划。

## 4. Amazon 初始通知内容

- 应用名称和 Application ID；
- 发现时间、事件时间范围和当前状态；
- 涉及的 Seller ID、Marketplace、数据类别和估算数量；
- 已采取的遏制措施；
- 当前已知原因和后续调查计划；
- 负责人的联系方式。

不得因信息尚未完全确认而延迟超过 24 小时；可先发送初始报告，再持续更新。

> 渠道核验：Amazon 在 2024-07-02 的官方公告中说明旧事件报告邮箱已不再监控。每次演练和真实事件前，应从当前 DPP/官方公告核验最新渠道，不依赖历史邮箱记录：
> https://developer-docs.amazon.com/sp-api/changelog/new-processes-for-reporting-security-incidents-and-informing-amazon-of-organizational-changes
