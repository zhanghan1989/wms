# Xiya 手动订单批量创建/删除接口文档

更新日期：2026-04-23

本文档用于提供给 Xiya 系统，对接 WMS 的“批量生成手动订单”和“删除手动订单”接口。

## 1. 对接目标

当 Xiya 侧需要把一批订单直接推送到 WMS，并在 WMS 中生成“手动订单”时，可以调用本接口。

WMS 收到请求后，会按每条订单里的 `productId` 判断当前走日本发还是中国发，并生成对应手动订单记录。

适用场景：

- Xiya 直接向 WMS 推送补单
- 人工订单由外部系统集中批量写入 WMS
- 不经过“亚马逊订单导入 TXT”的情况下，直接在 WMS 建单

## 2. 基础信息

Base URL：

```text
http://8.134.176.116:3000/api
```

接口返回时间字段为 ISO 8601 字符串，例如：

```text
2026-04-23T08:30:00.000Z
```

## 3. 鉴权方式

本接口使用第三方 API Key 鉴权。

推荐使用请求头：

```http
x-api-key: YOUR_THIRD_PARTY_API_KEY
```

也支持 Query 参数：

```text
?apiKey=YOUR_THIRD_PARTY_API_KEY
```

## 4. 接口信息

```http
POST /api/orders/manual/batch
```

完整地址：

```text
http://8.134.176.116:3000/api/orders/manual/batch
```

## 5. 请求说明

### 5.1 请求体结构

请求体使用 JSON：

```json
{
  "items": [
    {
      "orderId": "XIYA-M-20260423-001",
      "orderItemId": "XIYA-M-20260423-001-1",
      "sku": "fbm-pc18o-shengbei",
      "productId": "8736",
      "quantityPurchased": 1,
      "productName": "Evelyne伊芙琳 16/18 黑色 绸缎内胆包",
      "bloggerCooperationId": "XYJG-COOP-50237-1714215600000",
      "mallName": "Xiya",
      "shopName": "2号店-DGAZ store",
      "recipientName": "山田太郎",
      "buyerPhoneNumber": "09012345678",
      "shipPostalCode": "1000001",
      "shipState": "東京都",
      "shipAddress1": "千代田区千代田1-1-1",
      "shipAddress2": "XXビル 301",
      "shipAddress3": "",
      "shipmentCompany": "",
      "shipmentNo": ""
    }
  ]
}
```

### 5.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `items` | array | 是 | 要批量创建的手动订单列表，单次最多 500 条 |
| `items[].orderId` | string | 是 | 订单号 |
| `items[].orderItemId` | string | 否 | 明细号；不传时 WMS 自动生成 |
| `items[].sku` | string | 否 | SKU |
| `items[].productId` | string | 是 | 产品 ID；WMS 根据该值判断日本发/中国发 |
| `items[].quantityPurchased` | number/string | 是 | 数量，必须为正整数 |
| `items[].productName` | string | 否 | 商品名；不传时优先取主表产品名称 |
| `items[].bloggerCooperationId` | string | 否 | XYJG 博主合作单 ID；支持纯数字或 `XYJG-COOP-...` 格式。传入后 WMS 会在后续切中国发/登记日本发运单号时回推 XYJG |
| `items[].mallName` | string | 否 | 平台名称 |
| `items[].shopName` | string | 否 | 店铺名称 |
| `items[].recipientName` | string | 否 | 收件人 |
| `items[].buyerPhoneNumber` | string | 否 | 电话 |
| `items[].shipPostalCode` | string | 否 | 邮编 |
| `items[].shipState` | string | 否 | 都道府县/省 |
| `items[].shipAddress1` | string | 否 | 地址 1 |
| `items[].shipAddress2` | string | 否 | 地址 2 |
| `items[].shipAddress3` | string | 否 | 地址 3 |
| `items[].shipmentCompany` | string | 否 | 发货公司 |
| `items[].shipmentNo` | string | 否 | 发货单号；如果传入，WMS 会同时登记发货单号和登记时间 |

### 5.3 发货模式判断逻辑

WMS 不接受外部直接传入“发货模式”。

系统会根据 `productId` 对应主表产品的当前库存自动判断：

- 主表库存 `> 0`：生成 `日本発`
- 主表库存 `<= 0`：生成 `中国発`

### 5.4 事务规则

本接口为整批事务提交。

也就是说：

- 只要 `items` 里有任意一条数据校验失败，整批都不会创建
- 不会出现“前面几条成功，后面几条失败”的部分成功状态

```json
  "message": "请至少提供一条手动订单",
  "error": "Bad Request"
}
```

```json
{
  "statusCode": 400,
  "message": "items[0].productId不能为空",
  "error": "Bad Request"

```

### 8.5 某条记录数量非法

```json
{
  "statusCode": 400,
  "message": "items[1].quantityPurchased必须为正整数",
  "error": "Bad Request"
}
```

### 8.6 旧记录已经有运单号

如果 `orderId` 已存在，且 WMS 旧记录已经登记了运单号，则不会继续更新，Xiya 需要联系海外仓处理。

```json
{
  "statusCode": 409,
  "message": "订单 XIYA-M-20260423-001 已经有运单号，请联系海外仓处理",
  "error": "Conflict"
}
```

## 9. 删除手动订单接口

Xiya 如果需要删除已经推送到 WMS 的博主手动单，可以调用下面接口。

```http
POST /api/orders/manual/delete
```

完整地址：

```text
http://8.134.176.116:3000/api/orders/manual/delete
```

### 9.1 请求体结构

可以删除单个订单号：

```json
{
  "orderId": "XIYA-M-20260423-001"
}
```

也可以一次删除多个订单号：

```json
{
  "orderIds": ["XIYA-M-20260423-001", "XIYA-M-20260423-002"]
}
```

如果希望进一步限定博主合作单 ID，可额外传入：

```json
{
  "orderId": "XIYA-M-20260423-001",
  "bloggerCooperationId": "XYJG-COOP-50237-1714215600000"
}
```

### 9.2 删除规则

- 按 `orderId` 精确匹配 WMS 手动订单。
- 如果订单已经有运单号，接口返回 `409`，提示“已经有运单号，请联系海外仓处理”。
- 如果订单已经进入已确认、已生成 Yamato 等不可修改的拣货批次，接口返回 `409`，提示联系海外仓处理。
- 如果订单只是在未确认的拣货批次中，WMS 会同时从该拣货批次中移除该订单；如果批次因此变空，会自动删除该批次。

### 9.3 成功响应

```json
{
  "requestedCount": 2,
  "matchedCount": 2,
  "deletedCount": 2,
  "deletedOrderIds": ["XIYA-M-20260423-001", "XIYA-M-20260423-002"],
  "notFoundOrderIds": []
}
```

### 9.4 删除失败示例

```json
{
  "statusCode": 409,
  "message": "订单 XIYA-M-20260423-001 已经有运单号，请联系海外仓处理",
  "error": "Conflict"
}
```

## 10. 接入建议

建议 Xiya 按下面方式接入：

1. 先按业务组装好一批手动订单数据
2. 调用 `POST /api/orders/manual/batch`
3. 以返回的 `rows[].id` 作为 WMS 建单成功依据
4. 如接口返回 `400`，先修正整批数据后再整体重试

## 11. 注意事项

- WMS 会按 `orderId` 精确匹配已有手动订单：存在则更新旧记录，不重复建单；不存在才新建。若历史上已有多条相同 `orderId`，默认更新最新一条；但旧记录已经有运单号时不会更新，会返回 `409`。
- 若 `orderItemId` 不传，WMS 会自动生成一个明细号。
- `productId` 是发货判断核心字段，请确保传入的是 WMS 主表里的有效产品 ID。
- 如果传入 `bloggerCooperationId`，WMS 会做后续状态回推：判定为中国发或海外仓拣货缺货需要退回时，回推 `switch_to_china_ship=true`；日本发登记运单号后回推 `switch_to_china_ship=false` 和 `tracking_number`。
- 带 `bloggerCooperationId` 的手动订单如果已退回 XYJG，不会再进入 WMS 的普通“中国订单 / Xiya 拉单”队列，避免同一单重复流转。
- 回推 XYJG 失败不会阻断 WMS 建单，会记录在手动订单的回推状态字段中，后续可排查或重试。
- 如果需要后续继续扩展“外部单号回写”“批量改单”“批量取消”，建议继续沿用 `/api/orders/manual/*` 这一组接口路径。
