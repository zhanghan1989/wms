# 中国发与日中混发流程

适用日本时间2026年10月1日起首次导入的RMS API订单。全天每20分钟检查；导入提交后立即处理固定新規，不等待物流。勾选产品后通过同一“批量删除”按钮提交，后台按整单全部未删除明细判断：部分删除保留其余产品及物流/回传流程，后续商品邮件需核对正文；整单删除终止全部后续处理。已删产品禁止重导，原始记录与已发送证据保留。默认开关和暂停状态不因源码修改而改变。

## 中国发

新規 → 中国侧全部取得单号 → 中国発1 → 中国侧全部通関許可及清关日期 → 单号回传 → 中国発2。

中国発1依照既定业务规则，取得全部中国侧单号、登记日期、有效送付先ID后建立，正文为缺货、工厂安排、预计7–10日。新規已发送或人工忽略才允许继续。无需等待清关，也不推断工厂实际发货日期。

单号回传单独记录，必须等待新規已发送或人工忽略；不依赖中国発1是否已发送。全部中国包裹清关、日期及公司明确才回传，発送日采用清关日期。中国発2必须等待回传完成和中国発1已发送或人工忽略。

## 日中混发

新規 → 日本侧全部包裹已确认实际出货且单号资料完整 → 混発1 → 中国侧全部清关 → 中国侧单号回传 → 混発2。

混発1使用仓库第5步实际出货确认；登记单号与打印完成不能代替。列出日本侧商品及单号、中国侧商品与7–10日说明。中国侧尚无单号不阻止混発1。混発2等待中国側清关资料、回传和混発1完成，提供中国側配送信息。

混发按已确认业务规则只回传中国侧单号，每个订单一条回传记录。日本侧单号用于混発1通知，不另设日本側回传任务。

## 邮件和异常

通知关闭或邮件异常暂停时仍整理符合条件的任务，开关只控制发送。没有达到条件的阶段显示等待；任务整理不执行SMTP。

中国側单号由外部回传且已经核实一致时，中国発2/混発2建立为结果不确定，人工核实发送记录后确认已发送或明确重发。已有待发任务也受统一条件检查阻止自动发送。自身请求重试核实成功不重复回传。

新規不因商品修改或组合要求正文确认。其余邮件遇特殊说明、数量/SKU与购买资料不一致或组合资料不完整时人工预览修正；发送前核对模板版本和订单事实。任务唯一，不自动重发已完成事件。

SMTP结果不确定停止自动重发；明确临时失败退避重试最多10次；店铺认证/配置故障暂停后人工恢复。新規或首封邮件被取消会阻止后续；人工忽略允许继续，不能当作订单取消。

## 文案清理及限制

默认中国発2/混発2删除“本日発送”和“设置最短送达日”的矛盾措辞，改为通関許可及配送信息通知。已启用店铺模板独立保存，不自动覆盖，应在模板管理核实后启用新版。

中国発1仍以取得单号触发；首次取得单号时若已经清关，两封邮件可能在相邻检查轮次发送，暂未新增间隔或合并规则。CSV备用回传已整体删除，订单CSV导入保留。

本次没有部署、执行迁移或发送真实客户邮件。

## 执行安全规则（2026年10月13日确认）

混发只回传中国侧；已有回传按送付先及单号核实，不新增物流公司/日期匹配要求。所有回传必须等待新規已发送或明确人工忽略。失锁或心跳失败停止后续外部操作；已在途操作无法撤回。SMTP必须明确接受买家地址，只有BCC成功不能记客户邮件成功。领取邮件任务后重新核对逻辑删除、业务变更、发货类型、出货/清关、回传及前置邮件条件，并核对人工预览事实。运行记录超过30分钟但执行锁心跳仍有效不判中断；失联后才恢复超时任务，已开始SMTP的任务转结果不确定。


## 人工拆包订单

未拆包混发维持仅回传中国侧的规则。通过内部改号人工拆包后，同一原乐天订单的全部拆包单号统一回传：日本侧等待实际出货确认，中国侧等待通関許可及清关日期。内部A/B号用于仓库，不用于乐天API目标订单，也不产生额外新規邮件。
