# Xiya 订单对接接口文档

更新日期：2026-04-22

本文档用于 Xiya 系统对接 WMS 的“中国发订单”拉取与接收回执。

## 1. 对接目标

WMS 会把“中国订单处理一览 / 待 Xiya 拉取订单”中的订单通过接口提供给 Xiya。

Xiya 拉取订单并成功落库后，需要调用回执接口通知 WMS。WMS 收到回执后，会把对应订单标记为“已同步给 Xiya”，后续拉单接口不再重复返回这些订单。

对接流程：

1. Xiya 调用 `GET /api/orders/export` 拉取待处理中国发订单。
2. Xiya 将返回的订单写入 Xiya 系统。
3. Xiya 对已成功写入的订单调用 `POST /api/orders/export/ack` 回执。
4. WMS 标记这些订单为已同步，之后不再重复返回。

## 2. 基础信息

Base URL：

```text
http://8.134.176.116:3000/api
```

接口返回时间字段为 ISO 8601 字符串，例如：

```text
2026-04-22T03:30:00.000Z
```

WMS 内部主键字段 `id` 使用字符串返回。Xiya 回执时必须使用拉单接口返回的 `source + id`，不要使用平台订单号作为回执主键。

## 3. 鉴权方式

两个接口都需要第三方 API Key。

推荐使用请求头：

```http
x-api-key: xiya-t4HHGJWBDGg29yp8W8TK3QRQ3m1A
```

也支持 Query 参数：

```text
?apiKey=xiya-t4HHGJWBDGg29yp8W8TK3QRQ3m1A
```

建议 API Key 由 WMS 方通过单独安全渠道提供，不建议写在公开文档里。

## 4. 拉单接口

### 4.1 接口信息

```http
GET /api/orders/export
```

完整地址：

```text
http://8.134.176.116:3000/api/orders/export
```

### 4.2 返回哪些订单

该接口返回 WMS 当前“待 Xiya 拉取”的中国发订单。

会返回：

- 乐天订单
- 亚马逊订单
- 系统判断为中国发的订单
- 海外仓拣货过程中被切换为中国发的订单

不会返回：

- 已经被 Xiya 回执确认的订单
- 当前仍在海外仓拣货批次中、尚未切换为中国发的订单
- 已有发货单号的亚马逊订单
- 已发货状态的乐天订单

### 4.3 请求示例

```bash
curl -X GET "http://8.134.176.116:3000/api/orders/export" \
  -H "x-api-key: xiya-t4HHGJWBDGg29yp8W8TK3QRQ3m1A"
```

## 5. 接收回执接口

### 5.1 接口信息

```http
POST /api/orders/export/ack
```

完整地址：

```text
http://8.134.176.116:3000/api/orders/export/ack
```

### 5.2 使用时机

Xiya 成功把订单写入自己的系统后，再调用该接口。

不要在“刚拉到数据但还没写入成功”时回执，否则 WMS 会认为订单已被 Xiya 接收，后续不会再返回。

### 5.3 请求体

```json
{
  "items": [
    { "source": "rakuten", "id": "123" },
    { "source": "amazon", "id": "456" }
  ]
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `items` | array | 是 | 已成功接收的订单列表 |
| `items[].source` | string | 是 | `rakuten` / `amazon` |
| `items[].id` | string/number | 是 | 拉单接口返回的 `rows[].id` |

### 5.4 请求示例

```bash
curl -X POST "http://8.134.176.116:3000/api/orders/export/ack" \
  -H "Content-Type: application/json" \
  -H "x-api-key: xiya-t4HHGJWBDGg29yp8W8TK3QRQ3m1A" \
  -d '{
    "items": [
      { "source": "rakuten", "id": "123" },
      { "source": "amazon", "id": "456" }
    ]
  }'
```

### 5.5 成功响应

该接口成功时使用 WMS 标准响应格式：

```json
{
  "code": 0,
  "message": "OK",
  "data": {
    "acknowledgedAt": "2026-04-22T03:35:00.000Z",
    "requestedCount": 2,
    "rakutenCount": 1,
    "amazonCount": 1
  },
  "requestId": "9a6a95a9-4d9a-4b50-bbe7-f65f5fcb7e3f",
  "timestamp": "2026-04-22T03:35:00.123Z"
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `data.acknowledgedAt` | string | 回执确认时间 |
| `data.requestedCount` | number | 请求体中传入的订单数量 |
| `data.rakutenCount` | number | 实际成功确认的乐天订单数量 |
| `data.amazonCount` | number | 实际成功确认的亚马逊订单数量 |

说明：如果某条订单已经回执过，重复回执不会重复计数。因此 `requestedCount` 可能大于 `rakutenCount + amazonCount`。

## 6. 错误响应

错误响应使用 WMS 标准格式：

```json
{
  "code": 401,
  "message": "第三方接口密钥无效",
  "data": null,
  "requestId": "33f9b6c4-a3b1-4d36-9876-8a1d23e7b8c9",
  "timestamp": "2026-04-22T03:40:00.000Z"
}
```

常见错误：

| HTTP/Code | 场景 | message |
| --- | --- | --- |
| `401` | API Key 错误 | `第三方接口密钥无效` |
| `503` | WMS 未配置第三方 API Key | `未配置第三方接口密钥` |
| `400` | 回执 items 为空 | `请至少提供一条回执记录` |
| `400` | `source` 非法 | `items[i].source 只支持 rakuten 或 amazon` |
| `400` | `id` 非法 | `items[i].id必须是有效的整数ID` |

## 7. 对接注意事项

- `GET /api/orders/export` 成功响应是裸 JSON，请直接读取 `rows`，不是 `data.rows`。
- `POST /api/orders/export/ack` 成功响应是标准格式，请读取 `data`。
- 回执必须使用 `source + id`，不要使用 `注文ID` 或 `モール注文番号` 回执。
- Xiya 只应回执“已成功写入 Xiya 系统”的订单。
- 回执接口可重复调用，具备幂等效果；已回执过的订单不会重复计数。
- 如果 Xiya 拉单后没有回执，这些订单下次仍会继续返回。
