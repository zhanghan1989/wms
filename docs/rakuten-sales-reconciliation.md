# 乐天销售统计与对账

销售看板按RMS原订单和原购买SKU统计，商品销售额为商品总额减去订单优惠券，不扣积分、不加运费及支付手续费，排除800/900取消状态。日期按日本时间的下单日期；按月为完整自然月，近7/30/90天从首日日本时间零点开始。

`rakuten_sales_snapshots`保存原订单的销售事实，只保存商品标识、名称、数量、金额、取消状态，不复制客户个人资料。组合商品在原购买SKU下统计一次；订单优惠券按明细金额分摊，并分配整数日元余数，确保明细合计等于订单净销售额。仓库组件、人工拆分包裹、WMS产品排除和实际出库数量不作为财务计算来源。SKU销量因此是购买件数，与仓库出库组件件数可能不同。

对账只调用RMS的searchOrder/getOrder读取接口，按下单日期查询所有状态及所有商品，不调用导入订单、库存、物流回传或邮件流程。生产修复写入独立销售快照，不重写已发生的出库历史。每条新增、改价及取消的销售事实都与操作日志在同一事务提交，保留修改前后数据；覆盖周期只在整次查询和写入成功后推进。响应缺订单、金额缺失或明细与商品总额不符时停止对账，保留上次结果并展示异常。

每天日本时间03:10完整复核近180天，每小时40分复核近7天；首次同步补齐近180天。销售同步不触发仓库导入任务，也不改变已有导入、发货、邮件或库存任务的暂停设置。180天之外的改价需要管理员按指定期间重新对账。界面显示最近销售对账时间，未覆盖的统计期间不展示误导性的零销售额，也不能导出。

## 管理员回填

部署先执行迁移`20261027140000_add_rakuten_sales_snapshots`。然后在生产镜像内先预演：

```sh
docker exec wms_api node scripts/reconcile-rakuten-sales.cjs --shop='乐天-1号店' --from=2026-05-01 --to=2026-10-27 --operator=5
```

日期按日本时间，to包含当日，进行中的当日截止执行时刻。单次最多190天，新增覆盖期间须与已有覆盖期间连续。预演只读取、不写业务表。核对预演后使用相同参数加`--apply`写入。写入前自动在持久化`/app/storage/backups/rakuten-sales/`保存该店铺原销售快照与原覆盖状态，文件权限600；不备份凭证。operator必须为启用的管理员用户ID，实际使用前核对用户身份。

回滚财务数据时使用备份及销售对账审计记录恢复销售快照与覆盖状态，不修改仓库订单表。部署回滚可以继续保留新增表和可空连接字段。
