# Xiya 订单对接接口文档

更新日期：2026-04-16

本文档用于提供给 Xiya 系统，对接 WMS 的中国发订单拉取与回执接口。

## 1. 对接目标

Xiya 需要从 WMS 拉取“应走中国发”的订单，并在 Xiya 成功接单后回传确认，避免同一订单被重复拉取。

当前对接链路如下：

1. Xiya 调用 `GET /api/orders/export` 拉取待处理中国发订单。
2. WMS 返回“尚未被 Xiya 确认接收”的订单列表。
3. Xiya 成功落库后，调用 `POST /api/orders/export/ack` 回传已接收订单。
4. WMS 将这些订单标记为“已被 Xiya 接收”，后续 `GET /api/orders/export` 不再重复返回。

## 2. 鉴权方式

两个接口都使用同一套第三方 API Key 鉴权。

支持两种传法，任选其一：

1. 请求头：`x-api-key: <THIRD_PARTY_API_KEY>`
2. Query 参数：`?apiKey=<THIRD_PARTY_API_KEY>`

推荐统一使用请求头。

## 3. 基础说明

- Base URL 示例：`https://your-domain.com/api`
- 所有日期时间字段均为 ISO 8601 字符串，UTC 时区，例如：`2026-04-16T03:45:12.000Z`
- 所有数据库 `BigInt` 主键均以字符串返回
- 成功响应会带 `x-request-id` 响应头，便于排查问题

## 4. 拉单接口

### 4.1 接口信息

- Method：`GET`
- Path：`/api/orders/export`

### 4.2 业务规则

该接口返回当前“应走 Xiya 中国发”且“尚未被 Xiya 确认接收”的订单。

返回范围包括：

- 乐天订单
- 亚马逊订单
- 系统判断应走中国发的订单
- 海外仓拣货阶段手工切换为中国发的订单

不会重复返回以下订单：

- 已同步给 Xiya 且已确认接收的订单
- 当前仍在进行中的海外仓拣货批次中的普通海外仓订单

  -H "x-api-key: YOUR_THIRD_PARTY_API_KEY"

## 5. 回执接口

### 5.1 接口信息

- Method：`POST`
- Path：`/api/orders/export/ack`

### 5.2 使用时机

Xiya 在成功接单并完成本地落库后，再调用该接口。

建议不要在“刚拉到数据但尚未入库成功”时立即回执，否则可能造成订单不再返回但 Xiya 实际未接单。

### 5.3 请求体

```json
{
  "items": [
    { "source": "rakuten", "id": "123" },
    { "source": "amazon", "id": "456" }
  ]
}
```

### 5.4 请求字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `items` | array | 是 | 本次确认接收的订单列表 |
| `items[].source` | string | 是 | 平台来源：`rakuten` / `amazon` |
| `items[].id` | string | 是 | `GET /orders/export` 返回的 `rows[].id` |

### 5.5 成功响应格式

注意：这个接口成功时会走 WMS 全局响应包装，格式如下：

```json
{
  "code": 0,
  "message": "OK",
  "data": {
    "acknowledgedAt": "2026-04-16T04:25:10.000Z",
    "requestedCount": 2,
    "rakutenCount": 1,
    "amazonCount": 1
  },
  "requestId": "9a6a95a9-4d9a-4b50-bbe7-f65f5fcb7e3f",
  "timestamp": "2026-04-16T04:25:10.123Z"
}
```

### 5.6 响应字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `data.acknowledgedAt` | string(datetime) | 本次回执确认时间 |
| `data.requestedCount` | number | 请求中传入的订单条数 |
| `data.rakutenCount` | number | 实际成功确认的乐天订单条数 |
| `data.amazonCount` | number | 实际成功确认的亚马逊订单条数 |

说明：

- 如果某条记录之前已经回执过，则不会重复计入成功数量
- 因此 `requestedCount` 可能大于 `rakutenCount + amazonCount`

### 5.7 请求示例

```bash
curl -X POST "https://your-domain.com/api/orders/export/ack" \
  -H "Content-Type: application/json" \
  -H "x-api-key: YOUR_THIRD_PARTY_API_KEY" \
  -d '{
    "items": [
      { "source": "rakuten", "id": "123" },
      { "source": "amazon", "id": "456" }
    ]
  }'
```

## 6. 错误响应格式

如果鉴权失败、参数错误或服务端报错，接口会返回统一错误格式：

```json
{
  "code": 401,
  "message": "第三方接口密钥无效",
  "data": null,
  "requestId": "33f9b6c4-a3b1-4d36-9876-8a1d23e7b8c9",
  "timestamp": "2026-04-16T04:30:00.000Z"
}
```

常见错误：

| HTTP/Code | 场景 | 说明 |
| --- | --- | --- |
| `401` | API Key 错误 | `第三方接口密钥无效` |
| `503` | WMS 未配置第三方密钥 | `未配置第三方接口密钥` |
| `400` | 回执体为空 | `请至少提供一条回执记录` |
| `400` | `source` 非法 | `items[i].source 只支持 rakuten 或 amazon` |
| `400` | `id` 非法 | `items[i].id必须是有效的整数ID` |

## 7. 推荐接入流程

建议 Xiya 按下面顺序接入：

1. 定时调用 `GET /api/orders/export`
2. 逐条或批量写入 Xiya 本地系统
3. 仅对“已成功写入”的订单调用 `POST /api/orders/export/ack`
4. 记录 `id + source + requestId`
5. 如需重试，允许重复调用 `ack`，接口具备幂等效果

## 8. 对接注意事项

- `GET /api/orders/export` 成功响应是裸 JSON，解析时不要按 `data.rows` 读取，应直接读取 `rows`
- `POST /api/orders/export/ack` 成功响应则是标准包装格式，应读取 `data`
- `rows[].id` 是 WMS 订单记录主键，不是平台订单号；回执请使用这个 `id`
- `source + id` 组合可唯一标识一条要回执的订单记录
- `dispatchMode = china_pending` 表示该订单原本进入海外仓拣货流程，但后续被切换成中国发

## 9. 当前版本范围

当前文档对应的接口范围仅包含：

- 中国发订单导出
- 中国发订单接收回执

当前不包含：

- Xiya 发货结果回传
- Xiya 运单号回写
- Xiya 出库失败回滚
- 增量游标分页
